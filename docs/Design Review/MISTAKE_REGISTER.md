# Mistake register: what went wrong, how to detect it, how to avoid it

Purpose: stop repeating defects. Every entry is a real event in this project,
not a hypothetical. Add a line when something fails; do not delete entries when
they are fixed, mark them CLOSED with the date.

| ID | Mistake | How it was caught | Rule for next time | Status |
|---|---|---|---|---|
| M01 | Declared a defect before confirming the pin table. U1 pin 36 is named `SPICLK_N`, which looks like a flash-only pin, so the NeoPixel net was called broken. It is GPIO48 and the design is correct. | Cross-checked the pin against the package GPIO count and the module pin groups before writing it up | A single pin-name string is never evidence. Confirm the pin's alternate function from two independent sources before reporting a defect. | CLOSED, no action |
| M02 | A KiCad parser returned zero pads and it was nearly read as "the board has no nets". The file uses tab-indented, multi-line pad records. | Printed a known footprint block and compared with the regex | Before trusting a parser, run it against one record whose expected output you already know. A silent zero is a parser bug until proven otherwise. | CLOSED |
| M03 | Equated "DRC clean" with "board complete". The J2 board reports 0 DRC violations while five nets are unrouted. | Read the unconnected count, which is reported separately | Acceptance needs three numbers: DRC violations, unconnected items, schematic parity. Never quote one without the others. | OPEN by design, documented in `00_CONTINUATION_STATUS.md` |
| M04 | Ran a full autorouter pass because routing was incomplete, burnt 10 minutes and got 19 unrouted nets plus 73 violations | Compared the result with the hand-routed baseline | Diagnose the geometry first. If a whole pin row is walled in, no router setting will fix it. | CLOSED, Freerouting not re-run |
| M05 | Placed decoupling capacitors (C12, C13) directly in front of the QFN pad row, sealing the only escape corridor | Occupancy map of the F.Cu band in front of the pads | Count the escape corridors before placing parts near a fine-pitch edge. Decouplers belong on the far side, or on the same side but off the fanout axis. | OPEN, blocks routing |
| M06 | Attempted a board fix without the matching schematic change, which would have created a board that DRC accepts but the schematic does not describe | Reviewing what parity would compare | Fix the schematic first, regenerate, then route. A board change that has no schematic counterpart is a future silent failure. | AVOIDED |
| M07 | Firmware defaults to the SuperMini divider ratio because `RAMS_JLC_S3_J2` is defined nowhere in the repository, so battery voltage reads half of truth on this board | Grep of the whole repository for the build switch | A conditional build path that is never enabled is dead code with a bug inside. Verify the switch is set by a build file, not by hope. | OPEN, finding S7 |
| M08 | **Reported a hardware defect that existed only in my own tool.** Claimed the translator had `B` and `DIR` swapped on U6. TI SCES515 Table 4-1 gives DBV pin 4 = `B` and pin 5 = `DIR`, so the board (4=`NEO_SHIFT`, 5=`+3V3`) was right and the audit script's pin table was wrong. | Re-deriving the pinout from the vendor table row instead of from the script, after the docs, `circuit_spec.json` and the script disagreed | A pin-function table inside a checking tool is code, not evidence. Every row must cite the datasheet table it came from, and a HIGH finding must be re-derived from the vendor page before it is written into a review. Wrong tools manufacture false defects and waste a spin. | CLOSED 2026-11-11, no action; finding S1 withdrawn |
| M09 | Nearly accepted a fixture where a status LED was counted as working because a net existed, without checking that the net reached a pin that can drive it | Same review pass as M08 | Connectivity is not function. For every output, name the pin that sources it and the part that receives it. | CLOSED |
| M10 | Treated "part is DNP" as "part is verified". LED1 is DNP, which meant the invented data-path defect in S1 was never contradicted by a failing functional test. | Reviewing the DNP list against the findings | A DNP part still needs a correct schematic, and it also cannot falsify a defect claim. Test the path before declaring it broken. | CLOSED |
| M11 | Read a schematic-parity count out of an earlier record (0) and treated it as current; when the live board measured 41, the save step was blamed first. | Re-ran the same DRC on an untouched copy: 41 appeared with and without the save, and every item was a warning on an auto-generated `unconnected-(...)` net. | A number in a document is stale until it is re-measured on the file in front of you. Before blaming a tool, reproduce on an untouched copy. | CLOSED 2026-11-11 |
| M12 | Reported the 3D model set as present while two footprints pointed at files that do not exist (`SW_SPDT_Shouhan_MSK12C02.step`, `LED_WS2812B-2020_PLCC4_2.0x2.0mm.step`). A path string in a project file proves nothing about the installed library. | `kicad-cli pcb export step --subst-models` printed "Could not add 3D model" for both. | Resolve every asset path against the installed library, and prove the whole set loads with one export, before saying parts have bodies. | CLOSED 2026-11-11 |
| M13 | Sized the LDO thermal rise from 5 V, which is the USB connector voltage, not the regulator's input voltage. The SS14 sits in that path. | Recomputing `P = (V_in - 3.3) * I` with `V_in` = 4.55 V gave +57 C instead of +96 C at 250 mA. | Read the input voltage off the netlist at the specific pin, never from the connector. | CLOSED 2026-11-11 |

| M14 | Declared two datasheets "downloaded" without reading page 1 back. `BC817_bjt.pdf` and `SS14_diode.pdf` turned out to be byte-identical, so at least one part is documented by the wrong file, and it survived two review passes. | Hashing the datasheet folder during full verification. | A download is not a datasheet until page 1 is extracted and matched to the part number. Hash the folder after adding files; identical bytes mean one of them is wrong. | OPEN, both to be re-sourced |
| M15 | Treated a DRC-clean board as manufacturable. DRC compares the board with its own rule file, and that file accepted 0.45/0.20 vias - a 0.125 mm ring against a 0.13 mm process floor. | `verify_board.py` comparing measured geometry with the fabricator's published capability. | DRC proves internal consistency, not producibility. Every verification pass must compare geometry against the fabricator's numbers, never only against the project's own rules. | CLOSED 2026-11-11: the binding rule was the board's own m_MinClearance, not the netclass; set to 0.127 mm and 0.50 mm vias now pass with a 0.150 mm ring |
| M16 | Ran DRC and parity on every pass but never ran schematic ERC, while calling the design reviewed. A check that was never run is not a check that passed. | Listing every check the toolchain offers, by name, instead of following habit. | Enumerate all available checks and mark each run, skipped or failing. Silence in a report is not evidence of correctness. | CLOSED 2026-11-11, ERC reports 0 |

| M17 | Moved a two-pin decoupling cap from F.Cu to B.Cu and checked clearance on the outer layers only. The through via shorted `+3V3` and `MCU_EN` tracks on In2.Cu - 12 DRC errors. | DRC on the modified board named the exact inner-layer tracks. | A through via occupies every layer. Any placement or clearance check for a via must run against all copper layers, not the layer the part sits on. | CLOSED 2026-11-18, solver queries F.Cu, In1.Cu, In2.Cu and B.Cu |
| M18 | Excluded GND from the obstacle set because the via's partner pad is GND. The via carries `VDD_RF`, so an F.Cu GND track 0.027 mm away stayed invisible and reached DRC. | DRC reported 1 clearance violation at the via position. | Exclude only the net of the item being tested. "It connects to GND somewhere" is not "GND copper may be touched". | CLOSED 2026-11-18, per-query net exclusion |
| M19 | Mapped free space on a 0.40 mm grid and called it valid placement area. 0.50 mm vias fit inside a grid cell, so two existing vias (`SYS_EN` at 106.178,111.606 and `+3V3` at 107.104,111.885) read as free and the new pads landed on them. | DRC `shorting_items` and `hole_clearance` at those coordinates. | A sampling grid cannot see objects smaller than its step plus the clearance. Use exact geometry. | CLOSED 2026-11-18, exact distances |
| M20 | Scored candidate pad positions by corner distance. A via lying inside the pad rectangle scores as legal because every corner is far away. | Reading the candidate list back: a via at 106.178,111.606 sat inside the proposed rectangle and still passed. | For rectangles use point-to-rectangle distance, negative inside. The inside of a shape is the part that shorts. | CLOSED 2026-11-18 |

| M21 | Router treated a pad cell as an obstacle for its own net, so `search()` deleted the goal and every route stopped one 0.05 mm step short of the pad. | `track_dangling` twice and `track_not_centered_on_via` twice on every candidate; three good routes rejected. | Terminal cells belong to the net being routed. Snap the first and last node to the exact pad centre instead of the grid. | CLOSED 2026-11-19, `terminals()` / `anchor_of()` |
| M22 | The DRC gate compared a candidate against zero violations, not against the board's existing state, so two pre-existing dead-stub warnings rejected any correct route. | Every candidate reported exactly the same two VDD_RF `track_dangling` warnings and was thrown away. | Gate on the delta: reject only violations whose signature is not already in the baseline, and require the unconnected count to drop. | CLOSED 2026-11-19 |
| M23 | Treating dead copper as structural. The VDD_RF x = 110.3 wall and x = 110.0 stub fed nothing, but the cleanup was abandoned twice because "deleting one segment moves the open end". | The two DRC warnings on the board were those stubs, and both were 0.25 mm walls 0.05 mm from U1's pad tips, sealing pads 4-7. | A dangling warning names dead copper, not a topology to preserve. Delete the whole spur chain and let the gate prove the net is still whole. | CLOSED 2026-11-19, `scripts/drop_dead_vdd_rf_spurs.py`, DRC 0 warnings |
| M24 | Read a routing trial as a geometry limit when the trial had started from a board that already had two nets routed. | Repeated "exhausted" results for nets that route fine from the clean board. | Print and check the baseline hash and its unconnected count before interpreting a trial. | CLOSED 2026-11-19 |

| M25 | Added a named rule area to scope the 0.10 mm escape rules, then re-ran the router: all three nets reported `exhausted`. The router's obstacle mask treats every net-free zone as a keepout, so the new area masked the corridor it was created to open. | Printed the zone list (`GetZoneName`, `GetDoNotAllowTracks`) and saw `QFN_ESC` with tracks and vias allowed, then found it inside the keepout branch of `masks()`. | A rule area is not a keepout. When a helper classifies zones by net, it must also check what the zone actually forbids, and a named area that forbids nothing must be excluded explicitly. | CLOSED 2026-11-21, `masks()` skips `QFN_ESC` |
| M26 | Checked the +3V3 relief geometry against track centrelines only. Two candidates were rejected by DRC on items I never considered: VDD_RF's via at (108.65, 111.25) and GND's via at (109.32, 112.60), both 0.50 mm wide, both invisible to a centreline-only check. | DRC named the exact item pairs in the rejected candidate reports. | Same class as M17 and M19: a via is a 0.50 mm disc on every layer. Any candidate route in a dense strip must subtract every nearby via's radius, not just the tracks' half-widths. | CLOSED 2026-11-21, third candidate cleared both vias and passed |
| M27 | Treated 0.10 mm track and clearance as the thing that would unblock U1's left row. Measured at 0.10/0.10, the three remaining nets still report `exhausted`: U1.5's free area is a 0.85 x 0.30 mm pocket with every exit walled, and no 0.50 mm via fits in a 0.20 mm pad gap at any width. | Reachability pass on the router's own mask plus the printed DRC item pairs. | Capacity of a fine-pitch escape is set by via sites and crossing walls, not by track width. Measure the pocket before proposing a rule relaxation. | CLOSED 2026-11-21, option (a) disproven by measurement |
| M28 | Moved LORA_SCK_DEV's via to (112.10, 116.45) to merge the two LORA_SCK pockets and did not check VBAT_SENSE's B.Cu run at y 116.75, 0.30 mm below the new via. | DRC `shorting_items` LORA_SCK_DEV/VBAT_SENSE, plus one `track_dangling` from the dropped stub. | After any via move, recompute distance to the nearest copper on every layer within 0.5 mm, including runs that pass below the via's row. | REJECTED 2026-11-21, reverted by the gate |

## Recurring project-level failures already known

The inherited failure register in
`hardware/KiCAD Files/DeepSeek Build/05_FAILURE_MODES_AND_AI_RULES.md` lists
F01 - F38. The ones that keep coming back here are F21 (divider ratio versus
firmware), F13 (pin number versus GPIO number), F31 (clean DRC hiding an
incomplete board) and F34 (accepting a router result without reading it).
M03, M07 and M01 above are the same mistakes in a new costume; check that
register first before declaring a new class of problem.
