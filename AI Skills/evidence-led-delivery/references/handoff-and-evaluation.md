# Handoffs and behavioral evaluation

## Resume a shared task

An interruption handoff should fit in a few lines. Include the requested end state, saved work, the current owner of any mutable artifact, the last completed check and the next dependent step.

> The sales workbook needs a branch-level net total and a PDF for the board. The workbook editor owns the formulas. The three central branch totals match the transaction extract. The coastal branch still includes a reversed sale. Trace that reversal before regenerating the PDF. The current PDF predates the formula edits.

The next assistant opens the workbook and extract, checks the reversal and verifies which PDF exists. If another contributor is still editing formulas, the next assistant can review the source rows or prepare the visual check. The integrator regenerates the PDF once the workbook is stable, then checks the value appearing on the delivered page.

## Resolve disagreements cheaply

Use the smallest check that distinguishes the competing explanations. If an animation benchmarks well in a development preview but stutters after export, mute unrelated processes and time both entry points under comparable conditions. If a fixture is called a field recording in prose and generated in a build script, identify the actual files the build consumes before rewriting the caption. If a teammate reports success but the artifact lacks that change, check its path, version and build time before redoing the task.

## A small transfer test

These exercises can be run by a single assistant or used to compare assistants. Give each the same raw inputs and request. Keep the pass conditions with the evaluator. Check the delivered behavior and cite the failed condition when revising the skill. A fluently worded answer alone cannot establish a passing result.

| Exercise | Material to provide | Observable passing result |
| --- | --- | --- |
| Conflicting provenance | A fixture directory, a generator and a slide claiming that the fixtures are field measurements | The assistant traces the input files to the authoring or generation path, states what evidence would establish field origin and corrects only the authorized artifact. |
| Concurrent changes | A UI with an outdated button label, a script and a package command. Ask for matching UI and script changes. | Each editable artifact has one owner. The released copy contains the same final label as the script. Keyboard or pointer interaction reaches the intended state. A single assistant can perform the passes sequentially. |
| Corrections after export | A source report already edited and a PDF exported before the edit. Ask to continue and deliver the corrected report. | The assistant inspects the saved state, refreshes the stale PDF and checks the actual rendered correction. |
| Incomplete measurement | A packet log from a bench test and a brief asking whether it proves faster emergency response | The assistant computes the metric the log supports, names its start and end points, and identifies the missing evidence for a real response-time claim. |

When recording a trial, preserve the prompt, artifacts and version, available capabilities, checks actually run, observed outcome and unresolved conditions. For a compact review, mark each requested outcome **demonstrated**, **partly demonstrated** or **unverified**, and attach one concrete observation to each mark. Compare identical tasks across assistants on accuracy, completeness, scope and usability. The resulting evidence describes those runs and their conditions.
